நிதிச் சொல்லகராதி என்பது மேலே பொருத்தப்பட்ட நூலகம் அல்ல — அது மொழியிலேயே உள்ளது.
`வரவு`, `பற்று`, `வரி`, `இருப்புநிலை`, `பேரேடு`, `மூலதனம்` ஆகியவை லெக்சர் அறிந்த
திறவுச்சொற்கள்.

அவற்றுக்கு மேல் அமைவது — கணக்குப் பட்டியல், பேரேடு, GST, அறிக்கைகள் — **eTamil-இலேயே**
`nUlakam/kaNakkiyal/` இல் எழுதப்பட்டுள்ளது. இது வேண்டுமென்றே: கணக்கியல் கட்டமைப்புக்கு
Rust தேவைப்பட்டால், அது இருப்பதற்கான காரணத்துக்கே இந்த DSL போதுமானதாக இருக்காது.

## ரூபாய், இந்திய முறையில் பிரிக்கப்பட்டது

```etamil
இறக்கு "nUlakam/paNam.qmz";

அச்சு ரூபாய்(12345678.5);      // ₹1,23,45,678.50
```

லட்சம் மற்றும் கோடி பிரிப்பு; ஆயிரம் அல்ல. `paNam.qmz` `காசு_வடிவம்`, `காசாக`, `லட்சம்`,
`கோடி` ஆகியவற்றையும் தருகிறது.

## ஒரு GST விலைப்பட்டியல்

GST ஒரே மாநிலத்துக்குள் CGST மற்றும் SGST ஆகவும், மாநிலங்களுக்கு இடையே IGST ஆகவும்
பிரிகிறது. `examples/finance/vaNikavari_pattiyal.qmz` இலிருந்து முழுப் பிரிப்பு:

```etamil
// வரி_பிரிப்பு(தொகை, விகிதம், மாநிலம்_ஒன்றா)
செயல் வரி_பிரிப்பு(தொகை, விகிதம், மாநிலம்_ஒன்றா) {
    மொத்த_வரி = சதவீதம்(தொகை, விகிதம்);
    (மாநிலம்_ஒன்றா) எனில் {
        பாதி = வட்டமிடு(மொத்த_வரி / 2, 2);
        திரும்பு {மொத்தம்: மொத்த_வரி, cgst: பாதி, sgst: மொத்த_வரி - பாதி, igst: 0};
    }
    திரும்பு {மொத்தம்: மொத்த_வரி, cgst: 0, sgst: 0, igst: மொத்த_வரி};
}
```

இரண்டாவது `வட்டமிடு` அல்ல, `sgst: மொத்த_வரி - பாதி` என்பதைக் கவனியுங்கள். ஒற்றைப்படை
பைசாக்களை இரண்டாகப் பிரித்து இரு பாதிகளையும் முழுமைப்படுத்தினால் ஒரு பைசா இழக்கப்படும்
அல்லது உருவாக்கப்படும்; மீதியை எடுப்பது அதைச் செய்யாது. கீழே துல்லியமான தசமங்கள் இருப்பதால்,
CGST + SGST அமைப்பாலேயே மொத்தத்துக்குச் சமமாகிறது.

வரிசை உருப்படிகள் பதிவேடுகள்; விலைப்பட்டியல் அவற்றின் அணி:

```etamil
உருப்படிகள் = [
    {விவரம்: "மடிக்கணினி",   hsn: "8471", அளவு: 3,  விலை: 54999, விகிதம்: 18},
    {விவரம்: "விசைப்பலகை",   hsn: "8471", அளவு: 10, விலை: 1299,  விகிதம்: 18},
    {விவரம்: "அச்சுத்தாள்",   hsn: "4802", அளவு: 25, விலை: 320,   விகிதம்: 12}
];

ஒவ்வொரு உருப்படி இல் உருப்படிகள் {
    அடிப்படை = வரிசை_மதிப்பு(உருப்படி);
    வரி = வரி_பிரிப்பு(அடிப்படை, உருப்படி.விகிதம், உள்_மாநிலம்);
    ...
}
```

## இரட்டைப் பதிவுப் பேரேடு

```etamil
இறக்கு "nUlakam/kaNakkiyal/kaNakkukaL.qmz";
இறக்கு "nUlakam/kaNakkiyal/pErEtu.qmz";
இறக்கு "nUlakam/kaNakkiyal/aRikkYkaL.qmz";

கணக்குகள் = [
    மதிப்பு(கணக்கு_ஆக்கு("1000", "வங்கி",   வகை_சொத்து(), "நடப்பு")),
    மதிப்பு(கணக்கு_ஆக்கு("3000", "மூலதனம்", வகை_பங்கு(),  "பங்கு"))
];

பேரேடு = [];
பேரேடு = மதிப்பு(பதிவிடு(பேரேடு, பரிவர்த்தனை_ஆக்கு(
    "JV001", "2026-04-01", "தொடக்க மூலதனம்", [
        பற்று_வரிசை("1000", 500000),
        வரவு_வரிசை("3000", 500000)
    ])));

இருப்பாய்வு_அச்சிடு(இருப்பாய்வு(பேரேடு, கணக்குகள்));
```

இதை நான்கு வடிவமைப்பு முடிவுகள் ஒன்றாக நிறுத்துகின்றன:

**பேரேடு ஒரு மதிப்பு.** பதிவிடுதல் பழையதைத் திருத்தாமல் *புதிய* பேரேட்டைத் திருப்புகிறது;
எனவே ஒரு பதிவைப் பின்னால் மாற்ற முடியாது.

**இரட்டைப் பதிவு கட்டாயப்படுத்தப்படுகிறது.** இரு பக்கங்களும் ஒத்துப்போகாத பரிவர்த்தனையை
`பதிவிடு` மறுத்து `தவறு` திருப்புகிறது. சமநிலையற்ற எதுவும் பேரேட்டை அடைவதில்லை — மேலும்
தோல்வி ஒரு மதிப்பாக இருப்பதால், அழைப்பாளர் அதைக் கையாள வேண்டியிருக்கிறது.

**இருப்புகள் கணக்கின் சொந்தத் திசையில் படிக்கப்படுகின்றன.** பற்றை விட வரவு அதிகமுள்ள ஒரு
பொறுப்பு நேர்மறை; பற்று அதிகமுள்ள சொத்து நேர்மறையாக இருப்பது போலவே. ஒவ்வொரு அறிக்கையும்
`பற்று_இயல்பா` ஐச் சார்ந்துள்ளது.

**அறிக்கைகள் பேரேட்டிலிருந்து பெறப்படுகின்றன.** எதுவும் இருமுறை சேமிக்கப்படுவதில்லை; எனவே
ஒரு அறிக்கை அதன் பின்னாலுள்ள பதிவுகளுடன் முரண்பட முடியாது.

இக்கட்டமைப்பு [ekmungai/eloquent-ifrs](https://github.com/ekmungai/eloquent-ifrs) ஐ
முன்மாதிரியாகக் கொண்டது; IFRS பாணி வழங்கலுடன்.

## அடுத்து வருவது

கணக்கியல் மற்றும் வரிக் கட்டமைப்பு அடித்தளம்; முடிவுற்ற தொகுப்பு அல்ல. அதே பேரேட்டின்
மேல், அதே சொல்லகராதியுடன், மேலும் நான்கு துறைகள் திட்டமிடப்பட்டுள்ளன:

- **வங்கி** — NEFT மற்றும் UPI கட்டமைப்புகள், RBI இணக்கம், பரிவர்த்தனை வரம்புகள், KYC/AML சோதனைகள்
- **காப்பீடு** — பாலிசி, பிரீமியம், உரிமைகோரல் அமைப்புகள்; அதே துல்லியமான தசமக் கணிதத்தில்
- **சுங்கமும் வர்த்தகமும்** — மின்-வழி பில்கள், சுங்கச் சட்டக் குறியீடு சரிபார்ப்பு, வரிக் கணக்கீடு, அறிவிப்புகள்
- **பிளாக்செயின்** — Hyperledger அடிப்படையிலான தணிக்கைத் தடங்கள்; மொழியை விட்டு வெளியேறாமல் ஒரு பதிவைத் திருத்த முடியாததாக்கலாம்
